# 이진 탐색 트리 · 균형 트리

> BST 삽입/삭제, AVL(회전 4종), 2-3 트리, 2-3-4 트리, 레드-블랙 트리, 스플레이 트리, 최적 BST, B-트리(분할·합병), B+트리

## 1. 정의 / 핵심 성질

### 1.1 이진 탐색 트리 (BST)

#### 정의

모든 노드에 대해 왼쪽 서브트리의 키는 노드의 키보다 작고, 오른쪽 서브트리의 키는 노드의 키보다 큰 이진 트리이다.

#### 등장 배경

정렬된 배열은 이분 탐색으로 빠르게 찾을 수 있지만 삽입·삭제 때 원소를 밀어야 해서 `O(n)`이 걸린다. BST는 이분 탐색의 "절반씩 버리기"를 트리 구조로 옮겨, 탐색과 삽입·삭제를 모두 트리 높이만큼의 시간에 처리한다.

#### 구조

```
           50
         /    \
       30      70        ← 30 < 50 < 70
      /  \    /  \
    20   40  60   80     ← 30의 오른쪽(40)도 50보다는 작다
```

#### 성질

| 성질 | 설명 |
| --- | --- |
| 중위 순회하면 오름차순이 된다 | 왼쪽(작음) → 자신 → 오른쪽(큼) 순서로 방문한다 |
| 최솟값은 왼쪽 끝, 최댓값은 오른쪽 끝 노드이다 | 왼쪽으로 갈수록 작아진다 |
| 탐색·삽입·삭제는 `O(h)`이다 (h: 높이) | 비교할 때마다 한 레벨씩 내려간다 |
| 무작위 순서로 삽입하면 평균 높이가 약 `1.39 log₂ n`이다 | 평균적으로 균형에 가까운 모양이 된다 |
| 정렬된 순서로 삽입하면 높이가 n인 편향 트리가 된다 | 매번 한쪽 끝에만 붙는다 → `O(n)` |

#### 삭제

| 삭제할 노드 | 처리 |
| --- | --- |
| 리프 | 그냥 제거한다 |
| 자식 1개 | 그 자식을 삭제한 자리로 올린다 |
| 자식 2개 | 중위 후속자(오른쪽 서브트리의 최솟값) 또는 중위 선행자(왼쪽 서브트리의 최댓값)의 값을 가져오고, 그 노드를 대신 삭제한다 |

후속자·선행자는 자식이 최대 1개이므로 앞의 두 경우로 처리된다.

### 1.2 균형 트리의 필요성

BST는 삽입 순서에 따라 편향 트리가 되어 `O(n)`까지 느려진다. 삽입·삭제 때마다 모양을 조정해 높이를 항상 `O(log n)`으로 유지하는 트리를 균형 트리라 한다. 조정 방식에 따라 회전(AVL, 레드-블랙, 스플레이)과 분할·합병(2-3, 2-3-4, B-트리)으로 나뉜다.

### 1.3 AVL 트리

#### 정의

모든 노드의 균형 인수(BF)가 −1, 0, 1 중 하나인 BST이다.
- 균형 인수 `BF = 왼쪽 서브트리 높이 − 오른쪽 서브트리 높이`

#### 구조

```
           30 (+1)
          /     \
     20 (0)     40 (0)
     /    \
  10 (0)  25 (0)
```

#### 성질

| 성질 | 설명 |
| --- | --- |
| 높이는 약 `1.44 log₂(n+2)` 이하이다 | 높이 h의 최소 노드 수가 `N(h) = N(h−1) + N(h−2) + 1`로 피보나치처럼 늘어난다 (1, 2, 4, 7, 12, 20, 33 …) |
| 탐색·삽입·삭제가 항상 `O(log n)`이다 | 높이가 로그로 제한된다 |
| 삽입 후 회전은 최대 1번(단일 또는 이중)이다 | 가장 가까운 불균형 노드 하나를 고치면 그 위는 삽입 전 높이로 돌아간다 |
| 삭제 후 회전은 루트까지 `O(log n)`번 필요할 수 있다 | 회전으로 서브트리 높이가 줄어 위쪽에 새 불균형이 생길 수 있다 |

#### 회전

BF가 ±2가 된 노드 중 삽입 위치에서 가장 가까운 노드를 기준으로, 삽입이 어느 방향으로 두 번 내려갔는지에 따라 정한다.

| 유형 | 상황 | 해결 |
| --- | --- | --- |
| LL | 왼쪽 자식의 왼쪽 서브트리에 삽입 | 오른쪽 회전 1번 |
| RR | 오른쪽 자식의 오른쪽 서브트리에 삽입 | 왼쪽 회전 1번 |
| LR | 왼쪽 자식의 오른쪽 서브트리에 삽입 | 왼쪽 자식에서 왼쪽 회전 → 자신에서 오른쪽 회전 |
| RL | 오른쪽 자식의 왼쪽 서브트리에 삽입 | 오른쪽 자식에서 오른쪽 회전 → 자신에서 왼쪽 회전 |

```
LL: 오른쪽 회전                RR: 왼쪽 회전
      3                        1
     /            2             \             2
    2      →     / \             2     →     / \
   /            1   3             \         1   3
  1                                3
```

### 1.4 2-3 트리

#### 정의

모든 내부 노드가 2-노드 또는 3-노드이고, 모든 리프가 같은 레벨에 있는 탐색 트리이다.
- 2-노드: 키 1개, 자식 2개
- 3-노드: 키 2개, 자식 3개 (`왼쪽 < 키1 < 가운데 < 키2 < 오른쪽`)

#### 구조

```
             [20 | 40]
           /     |     \
       [10]    [30]    [50 | 60]
```

#### 성질

| 성질 | 설명 |
| --- | --- |
| 항상 완벽하게 균형을 이룬다 | 트리가 아래가 아니라 위(루트 분할)로 자란다 |
| 높이는 `log₃(n+1)`과 `log₂(n+1)` 사이이다 | 모두 3-노드면 가장 낮고, 모두 2-노드면 가장 높다 |
| 삽입 시 넘치면 분할한다 | 키가 3개가 되면 가운데 키를 부모로 올리고 둘로 나눈다. 루트가 분할되면 높이가 1 증가한다 |
| 삭제 시 모자라면 재분배하거나 합병한다 | 형제에게 키를 빌리거나, 부모 키를 내려 형제와 합친다 |
| 차수 3인 B-트리와 같다 | B-트리의 정의에 m = 3을 대입한 것이다 |

### 1.5 2-3-4 트리

#### 정의

2-노드, 3-노드, 4-노드(키 3개, 자식 4개)로 이루어지고 모든 리프가 같은 레벨에 있는 탐색 트리이다.

#### 성질

| 성질 | 설명 |
| --- | --- |
| 하향식(top-down) 삽입이 가능하다 | 루트에서 내려가면서 4-노드를 만나면 미리 분할하므로, 리프에 도착하면 항상 넣을 자리가 있다 |
| 한 번의 하향 경로로 삽입이 끝난다 | 위로 다시 올라가며 분할할 필요가 없다 |
| 레드-블랙 트리와 일대일로 대응한다 | 4-노드 = 검정 노드 + 빨강 자식 2개, 3-노드 = 검정 노드 + 빨강 자식 1개 |

### 1.6 레드-블랙 트리

#### 정의

각 노드가 빨강 또는 검정 색을 가지며 다음 다섯 조건을 만족하는 BST이다.
1. 모든 노드는 빨강 또는 검정이다.
2. 루트는 검정이다.
3. 모든 리프(NIL, 빈 자리)는 검정이다.
4. 빨강 노드의 자식은 모두 검정이다. (빨강이 연속으로 올 수 없다)
5. 임의의 노드에서 자손 리프까지 가는 모든 경로에 있는 검정 노드 수(흑색 높이)가 같다.

#### 등장 배경

AVL 트리는 균형 조건이 엄격해 삽입·삭제 때 회전이 잦다. 레드-블랙 트리는 균형 조건을 느슨하게 하여 회전 횟수를 상수로 제한하면서도 높이를 `O(log n)`으로 유지한다.

#### 구조

```
             20 (검정)
           /          \
      10 (검정)     30 (검정)
            \
           15 (빨강)
```

#### 성질

| 성질 | 설명 |
| --- | --- |
| 가장 긴 경로는 가장 짧은 경로의 2배 이하이다 | 짧은 경로는 검정만, 긴 경로는 검정·빨강 교대이며 검정 수는 같다 |
| 높이는 `2 log₂(n+1)` 이하이다 | 위 성질에서 유도된다 |
| 새 노드는 빨강으로 삽입한다 | 검정으로 넣으면 조건 5(흑색 높이)가 깨진다 |
| 삽입 시 회전은 최대 2번, 삭제 시 최대 3번이다 | 나머지 위반은 색 변경으로 처리한다 |

#### 삽입 후 조정 (부모가 빨강이라 조건 4 위반)

| 상황 | 처리 |
| --- | --- |
| 삼촌이 빨강 | 부모·삼촌을 검정, 조부모를 빨강으로 바꾸고 조부모에서 다시 검사한다 (2-3-4 트리의 4-노드 분할) |
| 삼촌이 검정, 꺾인 모양 | 부모에서 회전하여 일직선으로 만든 뒤 아래 경우로 처리한다 |
| 삼촌이 검정, 일직선 | 조부모에서 회전하고 부모와 조부모의 색을 바꾼다 |

### 1.7 스플레이 트리

#### 정의

균형 조건 없이, 접근(탐색·삽입·삭제)한 노드를 회전으로 루트까지 끌어올리는(splay) BST이다.

#### 등장 배경

실제 데이터는 최근에 쓴 것을 다시 쓰는 경우가 많다(접근 지역성). 자주 쓰는 키를 루트 근처로 옮겨 두면 반복 접근이 빨라진다. 균형 정보(높이, 색)를 저장할 필요도 없다.

#### 회전

| 종류 | 상황 | 처리 |
| --- | --- | --- |
| zig | 부모가 루트 | 한 번 회전 |
| zig-zig | 나와 부모가 같은 방향 자식 | 조부모에서 회전한 뒤 부모에서 회전 |
| zig-zag | 나와 부모의 방향이 다름 | 부모에서 회전한 뒤 조부모에서 회전 (AVL 이중 회전과 같다) |

#### 성질

| 성질 | 설명 |
| --- | --- |
| 연산 1번은 최악 `O(n)`이다 | 균형 조건이 없어 편향 트리가 될 수 있다 |
| 연산 m번의 합은 `O(m log n)`, 즉 분할상환 `O(log n)`이다 | splay가 경로 위 노드들의 깊이를 대략 절반으로 줄인다 |

### 1.8 최적 이진 탐색 트리

#### 정의

각 키의 탐색 확률이 주어졌을 때, 평균 비교 횟수가 가장 적은 BST이다.

#### 성질

| 성질 | 설명 |
| --- | --- |
| 자주 찾는 키가 루트 가까이에 온다 | 비교 횟수 = 깊이이므로 확률 × 깊이의 합을 줄인다 |
| 균형 트리가 최적이라는 보장은 없다 | 확률이 치우쳐 있으면 한쪽으로 기운 트리가 더 낫다 |
| 동적 계획법으로 `O(n³)`에 구한다 | `cost(i, j) = min (cost(i, k−1) + cost(k+1, j)) + w(i, j)`, `w(i, j)`는 구간의 확률 합 |
| 크누스 최적화로 `O(n²)`에 구한다 | 최적 루트가 `root[i][j−1] ≤ root[i][j] ≤ root[i+1][j]`를 만족하므로 k의 탐색 범위가 줄어든다 |

### 1.9 B-트리

#### 정의

차수 m인 B-트리는 다음 조건을 만족하는 다진 탐색 트리이다.
- 노드는 최대 m개의 자식과 `m − 1`개의 키를 가진다.
- 루트를 제외한 내부 노드는 최소 `⌈m/2⌉`개의 자식(`⌈m/2⌉ − 1`개의 키)을 가진다.
- 루트는 리프가 아니면 최소 2개의 자식을 가진다.
- 모든 리프는 같은 레벨에 있다.
- 노드 안의 키는 정렬되어 있고, 키 사이의 자식 포인터가 그 범위의 키를 담당한다.

#### 등장 배경

디스크는 한 번 읽을 때 블록 단위로 많은 데이터를 가져오지만, 읽는 횟수 자체가 매우 느리다. 이진 트리는 높이가 커서 디스크 접근이 많다. 노드 하나를 디스크 블록 하나에 맞추고 키를 많이 담으면 높이가 크게 낮아져 디스크 접근 횟수가 줄어든다.

#### 구조 (m = 4)

```
                  [ 30 | 60 ]
               /       |       \
      [10 | 20]    [40 | 50]    [70 | 80 | 90]
       < 30        30 ~ 60          > 60
```

#### 성질

| 성질 | 설명 |
| --- | --- |
| 높이가 `O(log_m n)`이다 | 노드마다 자식이 최소 `⌈m/2⌉`개이다 |
| 삽입 시 넘치면(overflow) 분할한다 | 키가 m개가 되면 가운데 키를 부모로 올리고 둘로 나눈다 |
| 삭제 시 모자라면(underflow) 재분배 또는 합병한다 | 형제에게 여유가 있으면 부모 키를 내리고 형제 키를 올린다. 없으면 형제 + 부모 키 + 자신을 합친다 |
| 내부 노드의 키를 삭제할 때는 리프의 키와 바꾼 뒤 삭제한다 | 선행자·후속자 키는 항상 리프에 있다 |

B* 트리는 노드를 2/3 이상 채우도록 하고, 넘치면 분할보다 형제로의 재분배를 먼저 시도하여 공간 활용도를 높인 변형이다.

### 1.10 B+트리

#### 정의

모든 데이터를 리프 노드에만 저장하고, 내부 노드에는 탐색을 위한 키(인덱스)만 두는 B-트리의 변형이다. 리프 노드는 연결 리스트로 이어져 있다.

#### 구조

```
                    [ 30 | 60 ]                  ← 인덱스 (키의 복사본)
                 /       |       \
     [10 20] → [30 40 50] → [60 70 80]           ← 리프: 실제 데이터, 서로 연결
```

#### 성질

| 성질 | 설명 |
| --- | --- |
| 범위 검색이 빠르다 | 시작 리프를 찾은 뒤 리프 연결을 따라가기만 하면 된다 |
| 탐색은 항상 리프까지 내려간다 | 데이터가 리프에만 있다. 대신 탐색 시간이 일정하다 |
| 내부 노드에 키를 더 많이 담는다 | 데이터가 없어 노드가 가벼우므로 팬아웃이 크고 높이가 낮다 |
| 리프 분할 시 가운데 키를 부모로 **복사**한다 | 리프에도 데이터로 남아야 한다. 내부 노드 분할은 B-트리처럼 **이동**한다 |
| 데이터베이스 인덱스와 파일 시스템에 쓰인다 | 디스크 접근 최소화와 범위 검색을 모두 만족한다 |

### 용어 정리

- **균형 인수 (BF)**: 왼쪽 서브트리 높이 − 오른쪽 서브트리 높이
- **회전**: 중위 순서(BST 조건)를 유지한 채 부모와 자식의 위치를 바꾸는 연산
- **중위 후속자 / 선행자**: 중위 순회에서 바로 다음 / 바로 앞 노드
- **흑색 높이**: 한 노드에서 리프까지 경로의 검정 노드 수 (자신 제외)
- **차수 (B-트리)**: 노드가 가질 수 있는 최대 자식 수
- **오버플로 / 언더플로**: 노드의 키가 최대를 넘음 / 최소에 못 미침
- **팬아웃**: 노드 하나가 가지는 자식 수

## 2. 연산별 시간복잡도

| 구조 | 탐색 | 삽입 | 삭제 | 높이 | 삽입 시 회전 |
| --- | --- | --- | --- | --- | --- |
| BST | 평균 `O(log n)`, 최악 `O(n)` | 같음 | 같음 | `log n` ~ `n` | 없음 |
| AVL | `O(log n)` | `O(log n)` | `O(log n)` | `≤ 1.44 log₂ n` | 최대 1번(단일/이중) |
| 2-3 / 2-3-4 | `O(log n)` | `O(log n)` | `O(log n)` | `log₃ n` ~ `log₂ n` | 분할 `O(log n)`번 |
| 레드-블랙 | `O(log n)` | `O(log n)` | `O(log n)` | `≤ 2 log₂(n+1)` | 최대 2번 (삭제 3번) |
| 스플레이 | 분할상환 `O(log n)` | 같음 | 같음 | 최악 `n` | 매 접근마다 |
| B-트리 (차수 m) | `O(log n)` | `O(log n)` | `O(log n)` | `O(log_m n)` | 분할/합병 |
| B+트리 | `O(log n)`, 범위 `O(log n + k)` | `O(log n)` | `O(log n)` | `O(log_m n)` | 분할/합병 |

## 3. 동작 과정

### BST 삭제 (자식 2개)

```
삭제 전            50 삭제 (후속자 60으로 대체)
      50                  60
     /  \                /  \
   30    70            30    70
        /  \                /  \
      60    80            65    80
        \
         65
```
- 50의 중위 후속자 = 오른쪽 서브트리 최솟값 60
- 60을 50 자리에 복사 → 원래 60 삭제 (자식 1개인 경우 → 65를 올림)

### AVL 삽입: 3, 2, 1, 4, 5, 6, 7

| 삽입 | 불균형 | 회전 | 결과 |
| --- | --- | --- | --- |
| 3, 2 | 없음 | | `3(2, _)` |
| 1 | 3의 BF = +2, LL | 3에서 오른쪽 회전 | `2(1, 3)` |
| 4 | 없음 | | `2(1, 3(_, 4))` |
| 5 | 3의 BF = −2, RR | 3에서 왼쪽 회전 | `2(1, 4(3, 5))` |
| 6 | 2의 BF = −2, RR (2→4→5) | 2에서 왼쪽 회전 | `4(2(1, 3), 5(_, 6))` |
| 7 | 5의 BF = −2, RR | 5에서 왼쪽 회전 | `4(2(1, 3), 6(5, 7))` |

정렬된 순서로 넣었는데도 최종 트리는 포화 이진 트리.

```
        4
      /   \
     2     6
    / \   / \
   1   3 5   7
```

### AVL 이중 회전: 3, 1, 2 (LR)

```
  3 (BF +2)        3              2
 /                /              / \
1 (BF −1)  →     2        →     1   3
 \              /
  2            1
    1에서 왼쪽 회전   3에서 오른쪽 회전
```

### 2-3 트리 삽입: 10, 20, 30, 40, 50

| 삽입 | 결과 |
| --- | --- |
| 10 | `[10]` |
| 20 | `[10 20]` |
| 30 | `[10 20 30]` 넘침 → 20 올림 → 루트 `[20]`, 자식 `[10]` `[30]` |
| 40 | 루트 `[20]`, 자식 `[10]` `[30 40]` |
| 50 | `[30 40 50]` 넘침 → 40 올림 → 루트 `[20 40]`, 자식 `[10]` `[30]` `[50]` |

### 2-3 트리 삭제: 위 결과에서 10 삭제

- `[10]`이 비어 underflow
- 형제 `[30]`은 키 1개(최소)라 빌려줄 수 없음 → 합병
- 부모 키 20을 내려 `[20 30]`으로 합침
- 결과: 루트 `[40]`, 자식 `[20 30]` `[50]`

### B-트리 (차수 5) 삽입

키 최대 4개, 최소 2개 (루트 제외).
- 1, 2, 3, 4 삽입 → `[1 2 3 4]`
- 5 삽입 → `[1 2 3 4 5]` 넘침 → 중간 3 올림 → 루트 `[3]`, 자식 `[1 2]` `[4 5]`

### B+트리 리프 분할 (차수 4, 리프 키 최대 3개)

- 리프 `[10 20 30]`에 40 삽입 → `[10 20 30 40]` 넘침
- `[10 20]`, `[30 40]`으로 분할, 30을 부모에 **복사** (리프에도 30 남음)
- 리프끼리 `[10 20] → [30 40]` 연결 유지

### 레드-블랙 삽입: 10, 20, 30, 15

| 삽입 | 상황 | 처리 | 결과 |
| --- | --- | --- | --- |
| 10 | 루트 | 검정으로 | `10B` |
| 20 | 부모 검정 | 그대로 | `10B(_, 20R)` |
| 30 | 부모 20R, 삼촌 NIL(검정), 일직선 | 10에서 왼쪽 회전, 20↔10 색 교환 | `20B(10R, 30R)` |
| 15 | 부모 10R, 삼촌 30R | 10·30 검정, 20 빨강 → 루트라 다시 검정 | `20B(10B(_, 15R), 30B)` |

### 스플레이 (zig-zig)

```
      G                 X
     /                   \
    P        →            P
   /                       \
  X                         G
```
X가 G의 왼쪽-왼쪽 손자 → G에서 오른쪽 회전, 다시 P에서 오른쪽 회전 → X가 위로.

## 4. 비교

| 기준 | AVL | 레드-블랙 | B/B+트리 | 스플레이 |
| --- | --- | --- | --- | --- |
| 균형 엄격도 | 엄격 (높이 차 ≤ 1) | 느슨 (최장 ≤ 최단 × 2) | 완전 균형 (리프 레벨 동일) | 없음 |
| 탐색 | 가장 빠름 | 약간 느림 | 디스크 접근 최소 | 분할상환 |
| 삽입/삭제 | 회전 많음 | 회전 적음 | 분할/합병 | 매번 splay |
| 추가 정보 | 높이 또는 BF | 색 1비트 | 노드 내 키 개수 | 없음 |
| 주 쓰임 | 탐색 위주 | Java `TreeMap`, C++ `std::map`, 리눅스 스케줄러 | DB 인덱스, 파일 시스템 | 캐시, 지역성 큰 접근 |

| 기준 | B-트리 | B+트리 |
| --- | --- | --- |
| 데이터 위치 | 모든 노드 | 리프에만 |
| 키 중복 | 없음 | 내부 노드에 복사본 |
| 범위 검색 | 중위 순회 필요 | 리프 연결 리스트 순회 |
| 탐색 길이 | 내부 노드에서 끝날 수 있음 | 항상 리프까지 |
| 팬아웃 | 작음 | 큼 (내부에 데이터 없음) |

## 5. Python 구현 / 라이브러리

- 표준 라이브러리에 균형 BST 없음
- 정렬 상태 유지가 필요하면 `bisect` + `list` (삽입 `O(n)`), 또는 힙/딕셔너리로 우회
- `sortedcontainers.SortedList`는 외부 라이브러리 (코딩 테스트에서 대부분 사용 불가)

```python
class Node:
    def __init__(self, key):
        self.key, self.left, self.right = key, None, None


def insert(root, key):
    if not root:
        return Node(key)
    if key < root.key:
        root.left = insert(root.left, key)
    elif key > root.key:
        root.right = insert(root.right, key)
    return root


def delete(root, key):
    if not root:
        return None
    if key < root.key:
        root.left = delete(root.left, key)
    elif key > root.key:
        root.right = delete(root.right, key)
    else:
        if not root.left:
            return root.right
        if not root.right:
            return root.left
        succ = root.right
        while succ.left:
            succ = succ.left
        root.key = succ.key
        root.right = delete(root.right, succ.key)
    return root
```

```python
# AVL 회전
def height(n):
    return n.h if n else 0

def rotate_right(y):
    x = y.left
    y.left = x.right
    x.right = y
    y.h = 1 + max(height(y.left), height(y.right))
    x.h = 1 + max(height(x.left), height(x.right))
    return x

def rotate_left(x):
    y = x.right
    x.right = y.left
    y.left = x
    x.h = 1 + max(height(x.left), height(x.right))
    y.h = 1 + max(height(y.left), height(y.right))
    return y
```
