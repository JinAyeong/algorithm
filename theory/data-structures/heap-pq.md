# 힙 · 우선순위 큐

> 완전 이진 트리 배열 표현(1-based/0-based 인덱스), 최대/최소 힙, 삽입·삭제 과정, bottom-up heapify가 O(n)인 이유, 최소-최대 힙, 좌향 트리, 이항 힙, 피보나치 힙

## 1. 정의 / 핵심 성질

### 1.1 우선순위 큐

#### 정의

각 원소가 우선순위를 가지며, 삽입 순서와 관계없이 우선순위가 가장 높은 원소를 먼저 삭제하는 추상 자료형이다.

#### 등장 배경

응급실 환자, 운영체제의 작업 스케줄링처럼 "가장 급한 것부터" 처리해야 하는 문제가 많다. 이를 기존 자료구조로 구현하면 한쪽 연산이 느려진다.

| 구현 | 삽입 | 최댓값 삭제 | 문제점 |
| --- | --- | --- | --- |
| 정렬되지 않은 배열 | `O(1)` | `O(n)` | 꺼낼 때마다 최댓값을 찾아야 한다 |
| 정렬된 배열 | `O(n)` | `O(1)` | 넣을 때마다 자리를 찾아 원소를 밀어야 한다 |

힙은 전체를 정렬하지 않고 "맨 위만 최대"인 상태를 유지하여 두 연산을 모두 `O(log n)`으로 처리한다.

### 1.2 힙

#### 정의

완전 이진 트리이면서, 모든 노드가 힙 성질을 만족하는 자료구조이다.
- 최대 힙: 부모 노드의 키가 자식 노드의 키보다 크거나 같다. 루트가 최댓값이다.
- 최소 힙: 부모 노드의 키가 자식 노드의 키보다 작거나 같다. 루트가 최솟값이다.

#### 구조

```
          50            ← 루트가 항상 최댓값
        /    \
      30      40        ← 부모는 자식보다 크다
     /  \    /
    10  20  35          ← 30과 40의 대소는 상관없다 (형제 사이에는 순서가 없다)

배열 (1번부터): [ _, 50, 30, 40, 10, 20, 35 ]
                    1   2   3   4   5   6
```

위에서 아래로, 왼쪽에서 오른쪽으로 번호를 매겨 배열에 저장한다.

#### 성질

| 성질 | 설명 |
| --- | --- |
| 모양은 항상 완전 이진 트리이다 | 삽입은 마지막 다음 칸에, 삭제는 마지막 칸을 루트로 옮기는 방식으로만 하기 때문이다 |
| 배열에 빈칸 없이 저장된다 | 완전 이진 트리는 번호 순서대로 빈틈없이 채워진다 |
| 노드 i의 자식은 `2i`, `2i + 1`, 부모는 `i // 2`이다 (1번부터 셀 때) | 레벨마다 노드 수가 2배씩 늘어나므로 번호도 2배씩 늘어난다 |
| 0번부터 세면 자식은 `2i + 1`, `2i + 2`, 부모는 `(i − 1) // 2`이다 | 1번부터 센 식에서 인덱스를 1씩 당긴 결과이다 |
| 높이는 `⌊log₂ n⌋ + 1`이다 (루트 레벨 0 기준이면 `⌊log₂ n⌋`) | 완전 이진 트리는 높이가 1 늘 때마다 노드를 2배 담을 수 있다 |
| 삽입과 삭제가 `O(log n)`이다 | 한 경로(루트 ↔ 리프)를 따라 교환하므로 높이만큼만 이동한다 |
| 리프는 `⌈n/2⌉`개, 내부 노드는 `⌊n/2⌋`개이다 | 마지막 내부 노드는 마지막 노드(n)의 부모인 `n // 2`번이다 |
| 리프의 번호는 1번부터 셀 때 `n//2 + 1` ~ `n`, 0번부터 셀 때 `n//2` ~ `n − 1`이다 | 마지막 내부 노드 다음부터가 리프이다. 0번부터 세면 마지막 내부 노드는 `n//2 − 1`번이다 |
| 형제 사이, 서로 다른 서브트리 사이에는 순서가 없다 | 힙 성질은 부모-자식 관계만 규정한다. 이를 반정렬 상태라 한다 |
| 최대 힙에서 최솟값은 리프 중 하나이다 | 자식이 있는 노드는 자식보다 크므로 최솟값이 될 수 없다 |
| 최대 힙에서 2번째로 큰 값은 루트의 자식 중 하나이다 | 루트를 제외하면 각 서브트리의 최댓값은 그 서브트리의 루트이다 |
| 3번째로 큰 값은 레벨 2 또는 3에 있고, k번째로 큰 값은 레벨 2 ~ k 어디든 올 수 있다 | k번째 큰 값보다 큰 조상은 최대 `k − 1`개이므로 깊이가 k를 넘을 수 없다 |

### 1.3 힙의 연산

#### 삽입 (up-heap)

1. 새 원소를 마지막 위치(n + 1번)에 넣는다. 완전 이진 트리 모양이 유지된다.
2. 부모와 비교하여 힙 성질을 어기면 교환한다.
3. 루트에 닿거나 부모가 더 크면 멈춘다.

비교는 최대 `⌊log₂ n⌋`번이다.

#### 삭제 (down-heap)

1. 루트(최댓값)를 꺼낸다.
2. 마지막 노드를 루트 자리로 옮긴다.
3. 두 자식 중 **더 큰 자식**과 비교하여 작으면 교환한다. 더 큰 자식과 바꿔야 새 부모가 다른 자식보다도 크다.
4. 리프에 닿거나 자식보다 크면 멈춘다.

레벨마다 비교 2번(자식끼리 1번, 부모와 1번)이므로 최대 약 `2 log₂ n`번이다.

#### 생성

| 방법 | 절차 | 복잡도 |
| --- | --- | --- |
| 하나씩 삽입 (top-down) | 빈 힙에 n번 삽입한다 | `O(n log n)` |
| 상향식 구성 (bottom-up heapify) | 배열을 그대로 두고 마지막 내부 노드(`n // 2`)부터 루트까지 거꾸로 down-heap 한다 | `O(n)` |

두 방법은 모두 올바른 힙을 만들지만 결과 배열은 다를 수 있다.

#### 상향식 구성이 O(n)인 이유

- 아래에서 잰 높이가 h인 노드는 최대 `n / 2^(h+1)`개이고, 각각 최대 h번 이동한다.
- 리프(전체의 1/2)는 이동이 0번, 그 위 1/4은 1번, 그 위 1/8은 2번이다.
- 전체 이동 횟수는 `Σ h · n / 2^(h+1)` ≤ `n`이다.
- 노드 대부분이 아래쪽에 있고, 아래쪽 노드일수록 이동 거리가 짧기 때문이다.
- 하나씩 삽입하면 아래쪽 노드가 루트까지 올라갈 수 있어 `O(n log n)`이 된다.

### 1.4 최소-최대 힙

#### 정의

레벨이 번갈아 최소 레벨과 최대 레벨로 구성된 완전 이진 트리이다. 루트는 최소 레벨이다.
- 최소 레벨의 노드: 자기 서브트리에서 가장 작은 값이다.
- 최대 레벨의 노드: 자기 서브트리에서 가장 큰 값이다.

#### 등장 배경

최솟값과 최댓값을 모두 꺼내야 하는 양방향 우선순위 큐를 하나의 구조로 처리하기 위해 고안되었다.

#### 구조

```
최소 레벨           5           ← 전체 최솟값
                 /     \
최대 레벨      70       40      ← 둘 중 큰 70이 전체 최댓값
              /  \     /
최소 레벨    30    9   15
```

#### 성질

| 성질 | 설명 |
| --- | --- |
| 최솟값은 루트이다 | 루트는 최소 레벨이므로 트리 전체의 최솟값이다 |
| 최댓값은 루트의 두 자식 중 큰 쪽이다 | 루트의 자식은 최대 레벨이므로 각 서브트리의 최댓값이다 |
| 삽입·삭제는 `O(log n)`이다 | 조부모 단위로 비교하며 이동하므로 높이에 비례한다 |

비슷한 구조로 디프(deap)가 있다. 루트를 비워 두고 왼쪽 서브트리는 최소 힙, 오른쪽 서브트리는 최대 힙으로 운영한다.

### 1.5 좌향 트리 (leftist tree)

#### 정의

모든 노드에서 왼쪽 자식의 `s` 값이 오른쪽 자식의 `s` 값보다 크거나 같은 이진 트리 형태의 힙이다.
- `s(x)`: 노드 x에서 가장 가까운 빈 자리(null)까지의 거리이다. null의 s는 0이다.

#### 등장 배경

이진 힙 두 개를 합치려면 처음부터 다시 만들어야 하므로 `O(n)`이 걸린다. 좌향 트리는 합병을 `O(log n)`에 하기 위해 고안되었다.

#### 구조

```
           2  (s=2)
          / \
   (s=2) 5   7  (s=1)
        / \
       6   9          ← 왼쪽으로 치우친 모양
```

#### 성질

| 성질 | 설명 |
| --- | --- |
| 완전 이진 트리가 아니다 | 모양 조건이 "왼쪽 s ≥ 오른쪽 s"뿐이다 |
| 오른쪽 끝 경로의 길이는 `log₂(n+1)` 이하이다 | s가 k이면 위쪽 k레벨이 꽉 차 있어 노드가 `2^k − 1`개 이상이다 |
| 합병이 `O(log n)`이다 | 합병은 오른쪽 경로만 따라 내려가므로 짧은 경로만 처리한다 |
| 삽입과 삭제는 합병으로 처리한다 | 삽입은 노드 1개짜리 트리와의 합병, 삭제는 루트를 뗀 두 서브트리의 합병이다 |

### 1.6 이항 힙 (binomial heap)

#### 정의

이항 트리들의 모음으로 이루어진 힙이다. 각 이항 트리는 최소 힙 순서를 따르고, 같은 차수의 트리는 두 개 이상 없다.
- 이항 트리 `B_k`: `B_(k−1)` 두 개를 한쪽 루트가 다른 쪽 루트의 자식이 되도록 연결한 트리이다. `B_0`은 노드 1개이다.

#### 구조

```
B_0    B_1     B_2          B_3
 o      o       o            o
        |      /|          / | \
        o     o o         o  o  o
              |          /|  |
              o         o o  o
                        |
                        o
```

#### 성질

| 성질 | 설명 |
| --- | --- |
| `B_k`는 노드 `2^k`개, 높이 k, 루트 차수 k이다 | 같은 트리 두 개를 이어 붙이므로 노드 수가 2배, 높이와 차수가 1씩 는다 |
| `B_k`에서 깊이 d의 노드 수는 `C(k, d)`이다 | 이름이 "이항" 트리인 이유이다 |
| 노드 n개 이항 힙의 트리 구성은 n의 이진 표현과 같다 | 13 = 1101₂ → `B_3`, `B_2`, `B_0` |
| 합병은 이진수 덧셈과 같고 `O(log n)`이다 | 같은 차수 두 개가 만나면 하나로 연결해 다음 차수로 올린다 |

### 1.7 피보나치 힙

#### 정의

이항 힙의 정리 작업을 최대한 미룬 느슨한 힙이다. 트리들을 루트 리스트에 그냥 추가해 두었다가 최솟값을 삭제할 때 한꺼번에 정리한다.

#### 등장 배경

다익스트라와 프림 알고리즘은 키 감소(decrease-key) 연산을 최대 E번 수행한다. 이 연산을 `O(1)`로 만들어 두 알고리즘을 `O(E + V log V)`로 줄이기 위해 고안되었다.

#### 성질

| 성질 | 설명 |
| --- | --- |
| 삽입·합병·키 감소가 분할상환 `O(1)`이다 | 트리를 루트 리스트에 붙이기만 하고 정리를 미룬다 |
| 최솟값 삭제는 분할상환 `O(log n)`이다 | 미뤄 둔 정리(같은 차수 트리 합치기)를 이때 수행한다 |
| 키 감소 시 부모와 잘라낸다 | 부모가 이미 자식을 하나 잃었다면 부모도 잘라낸다(연쇄 잘라내기, cascading cut). 트리가 너무 앙상해지는 것을 막는다 |
| 실제로는 이진 힙보다 느린 경우가 많다 | 상수 계수와 포인터 관리 비용이 크다 |

### 용어 정리

- **완전 이진 트리**: 마지막 레벨을 제외하고 모두 차 있으며, 마지막 레벨은 왼쪽부터 채워진 이진 트리
- **포화 이진 트리**: 모든 레벨이 꽉 찬 이진 트리. 완전 이진 트리의 특수한 경우
- **힙 성질**: 부모와 자식 사이의 대소 관계 조건
- **up-heap / down-heap**: 원소를 위로 / 아래로 교환하며 힙 성질을 회복하는 과정. sift-up / sift-down이라고도 한다
- **heapify**: 임의의 배열을 힙으로 만드는 과정
- **키 감소 (decrease-key)**: 힙 안에 있는 원소의 키를 줄이고 힙 성질을 회복하는 연산

## 2. 연산별 시간복잡도

| 힙 | 최솟값 조회 | 삽입 | 최솟값 삭제 | 키 감소 | 합병 |
| --- | --- | --- | --- | --- | --- |
| 이진 힙 | `O(1)` | `O(log n)` | `O(log n)` | `O(log n)` | `O(n)` |
| 최소-최대 힙 | `O(1)` (최댓값도 `O(1)`) | `O(log n)` | `O(log n)` | `O(log n)` | `O(n)` |
| 좌향 트리 | `O(1)` | `O(log n)` | `O(log n)` | `O(log n)` | `O(log n)` |
| 이항 힙 | `O(1)`* | `O(log n)`, 분할상환 `O(1)` | `O(log n)` | `O(log n)` | `O(log n)` |
| 피보나치 힙 | `O(1)` | `O(1)` | 분할상환 `O(log n)` | 분할상환 `O(1)` | `O(1)` |

\* 최솟값 루트 포인터를 유지할 때. 안 하면 루트들을 훑어 `O(log n)`.

| 우선순위 큐 구현 | 삽입 | 최댓값 삭제 |
| --- | --- | --- |
| 정렬 안 된 배열 | `O(1)` | `O(n)` |
| 정렬된 배열 | `O(n)` | `O(1)` |
| 균형 BST | `O(log n)` | `O(log n)` |
| 힙 | `O(log n)` | `O(log n)` |

| 힙 생성 | 복잡도 |
| --- | --- |
| n번 삽입 | `O(n log n)` |
| bottom-up heapify | `O(n)` |

## 3. 동작 과정

### 최대 힙 삽입

힙 `[50, 30, 40, 10, 20, 35]` (1-based), 45 삽입

```
        50                     50
      /    \                 /    \
    30      40      →      30      45
   /  \    /  \           /  \    /  \
  10  20  35  [45]       10  20  35   40
```
1. 위치 7에 45
2. 부모(위치 3) 40 < 45 → 교환
3. 부모(위치 1) 50 > 45 → 멈춤
- 결과 `[50, 30, 45, 10, 20, 35, 40]`

### 최대 힙 삭제

`[50, 30, 45, 10, 20, 35, 40]`에서 삭제
1. 루트 50 꺼냄, 마지막 40을 루트로 → `[40, 30, 45, 10, 20, 35]`
2. 자식 30, 45 중 큰 45 > 40 → 교환 → `[45, 30, 40, 10, 20, 35]`
3. 위치 3의 자식은 위치 6(35)뿐, 35 < 40 → 멈춤
- 결과 `[45, 30, 40, 10, 20, 35]`

### bottom-up heapify vs 하나씩 삽입

입력 `[10, 20, 5, 30, 15, 8, 40]` (n = 7), 최대 힙

bottom-up (마지막 내부 노드 `7 // 2 = 3`부터)

| i | 값 | 자식 | 동작 | 배열 |
| --- | --- | --- | --- | --- |
| 3 | 5 | 8, 40 | 40과 교환 | `[10, 20, 40, 30, 15, 8, 5]` |
| 2 | 20 | 30, 15 | 30과 교환 | `[10, 30, 40, 20, 15, 8, 5]` |

### 좌향 트리 합병 (최소 힙)

```
  A:   2            B:   5
      / \               /
     7   9             6
```
- s 값: A의 7, 9는 s=1, 2는 s=2 / B의 6은 s=1, 5는 s=1 (오른쪽이 null)
1. 루트 2 < 5 → 2가 루트. 2의 오른쪽(9)과 B를 합병
2. 5 < 9 → 5가 루트. 5의 오른쪽(null)과 9를 합병 → 9
3. 5의 왼쪽 6(s=1), 오른쪽 9(s=1) → 조건 만족, s(5) = 2
4. 2로 돌아옴: 왼쪽 7(s=1) < 오른쪽 5(s=2) → 좌우 교환

```
       2
      / \
     5   7
    / \
   6   9
```

### 이항 힙 합병

`H1` = {B_0, B_1} (노드 3개 = 011₂), `H2` = {B_0, B_2} (노드 5개 = 101₂) → 노드 8개 = 1000₂
1. B_0 + B_0 → B_1 (올림)
2. B_1 + B_1(올림) → B_2 (올림)
3. B_2 + B_2(올림) → B_3
- 결과 {B_3} 하나

## 5. Python 구현 / 라이브러리

- `heapq`: **최소 힙**, 0-based `list` 그대로 사용
  - `heappush(h, x)`, `heappop(h)`, `heapify(h)` (`O(n)`)
  - `heappushpop(h, x)`: push 후 pop (한 번에, 더 빠름)
  - `heapreplace(h, x)`: pop 후 push
  - `nlargest(k, it)`, `nsmallest(k, it)`
- 최대 힙: 값에 `−` 붙여서 넣기
- 우선순위 + 값: 튜플 `(priority, value)`. 우선순위가 같으면 두 번째 원소로 비교하니 비교 불가 객체는 `(priority, count, obj)`
- `queue.PriorityQueue`: 스레드 안전 버전, 느림

```python
import heapq

h = []
heapq.heappush(h, 3)
heapq.heappush(h, 1)
heapq.heappop(h)            # 1

max_h = []
heapq.heappush(max_h, -5)   # 최대 힙
-heapq.heappop(max_h)       # 5
```

```python
# 직접 구현 (최대 힙, 1-based)
class MaxHeap:
    def __init__(self):
        self.a = [None]

    def push(self, x):
        a = self.a
        a.append(x)
        i = len(a) - 1
        while i > 1 and a[i // 2] < a[i]:
            a[i], a[i // 2] = a[i // 2], a[i]
            i //= 2

    def pop(self):
        a = self.a
        top = a[1]
        last = a.pop()
        if len(a) > 1:
            a[1] = last
            self._down(1)
        return top

    def _down(self, i):
        a, n = self.a, len(self.a) - 1
        while 2 * i <= n:
            c = 2 * i
            if c + 1 <= n and a[c + 1] > a[c]:
                c += 1
            if a[i] >= a[c]:
                break
            a[i], a[c] = a[c], a[i]
            i = c

    def heapify(self, arr):
        self.a = [None] + arr
        for i in range(len(arr) // 2, 0, -1):
            self._down(i)
```
