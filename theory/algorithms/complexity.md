# 시간복잡도

> 빅오·빅오메가·빅세타, 점화식 풀이, 마스터 정리, 분할상환 분석

## 1. 정의 / 핵심 성질

### 1.1 시간복잡도

#### 정의

알고리즘이 입력 크기 n에 대해 수행하는 기본 연산의 횟수를 n의 함수로 나타낸 것이다.

#### 등장 배경

실제 실행 시간은 컴퓨터 성능, 언어, 구현 방식에 따라 달라진다. 이런 환경 요인을 빼고 알고리즘 자체의 효율을 비교하기 위해, 실행 시간 대신 기본 연산(비교, 대입 등)의 횟수가 n에 따라 얼마나 빨리 늘어나는지를 본다.

#### 성질

| 성질 | 설명 |
| --- | --- |
| 같은 알고리즘도 입력에 따라 최선·평균·최악 복잡도가 다르다 | 삽입 정렬은 정렬된 입력에서 `n − 1`번, 역순 입력에서 `n(n−1)/2`번 비교한다 |
| 보통 최악 복잡도로 비교한다 | 어떤 입력이 와도 그 이상 걸리지 않는다는 보장을 준다 |
| 공간복잡도도 같은 방식으로 나타낸다 | 입력 외에 추가로 쓰는 메모리를 n의 함수로 쓴다 |

### 1.2 점근 표기법

#### 정의

n이 충분히 클 때 함수의 증가율만 남기고 상수 계수와 낮은 차수 항을 버려서 나타내는 표기법이다.

| 표기 | 의미 | 정의 |
| --- | --- | --- |
| `O(g(n))` (빅오) | 점근적 상한. 아무리 커도 g의 상수배를 넘지 않는다 | `f(n) ≤ c·g(n)` (모든 `n ≥ n0`)인 양수 c, n0가 존재 |
| `Ω(g(n))` (빅오메가) | 점근적 하한. 아무리 작아도 g의 상수배 이상이다 | `f(n) ≥ c·g(n)` (모든 `n ≥ n0`)인 양수 c, n0가 존재 |
| `Θ(g(n))` (빅세타) | 상한이자 하한. g와 같은 증가율이다 | `c1·g(n) ≤ f(n) ≤ c2·g(n)` (모든 `n ≥ n0`) |
| `o(g(n))` (리틀오) | 엄격한 상한. g보다 확실히 느리게 증가한다 | `f(n) / g(n) → 0` |
| `ω(g(n))` (리틀오메가) | 엄격한 하한. g보다 확실히 빠르게 증가한다 | `f(n) / g(n) → ∞` |

#### 등장 배경

`3n² + 10n + 5`와 `n²`은 n이 작을 때는 차이가 크지만, n이 커질수록 `n²` 항이 전체를 지배한다. 큰 입력에서의 효율을 비교하는 데는 가장 빠르게 커지는 항만 보면 충분하다.

#### 증가 순서

```
1 < log n < √n < n < n log n < n² < n³ < 2ⁿ < n! < nⁿ
```

#### 성질

| 성질 | 설명 |
| --- | --- |
| `3n² + 10n = O(n²)`이다 | n ≥ 10이면 `10n ≤ n²`이므로 `3n² + 10n ≤ 4n²` (c = 4, n0 = 10) |
| `O(n²)`인 함수는 `O(n³)`이기도 하다 | O는 상한이므로 더 큰 상한도 참이다. 관례상 가장 작은 상한을 쓴다 |
| `f = Θ(g)` ⇔ `f = O(g)`이고 `f = Ω(g)`이다 | Θ의 정의가 두 부등식을 동시에 요구한다 |
| 로그의 밑은 무시한다 (`log₂ n = Θ(log₁₀ n)`) | 밑 변환 공식 `log₂ n = log₁₀ n / log₁₀ 2`에 의해 상수배 차이이다 |
| `log(n!) = Θ(n log n)`이다 | `n! ≤ nⁿ`이고 `n! ≥ (n/2)^(n/2)`이므로 양쪽 모두 `n log n`의 상수배이다 |
| 다항 함수는 지수 함수보다 느리게 증가한다 (`n^k = o(2ⁿ)`) | `n^k / 2ⁿ → 0` |
| 최선/평균/최악과 O/Ω/Θ는 서로 다른 개념이다 | 앞은 "어떤 입력인가", 뒤는 "함수의 범위"이다. 퀵 정렬의 최악은 `Θ(n²)`, 최선은 `Θ(n log n)`이다 |

### 1.3 점화식과 마스터 정리

#### 정의

- 점화식: 재귀 알고리즘의 수행 시간을 더 작은 입력의 수행 시간으로 나타낸 식이다. 예: `T(n) = 2T(n/2) + n`
- 마스터 정리: `T(n) = a·T(n/b) + f(n)` (a ≥ 1, b > 1) 꼴의 점화식을 `n^(log_b a)`와 `f(n)`의 크기 비교만으로 푸는 정리이다.

#### 성질

| 경우 | 조건 | 결과 | 설명 |
| --- | --- | --- | --- |
| 1 | `f(n)`이 `n^(log_b a)`보다 다항식만큼 작다 | `Θ(n^(log_b a))` | 재귀 트리의 아래쪽(리프)으로 갈수록 비용이 커져, 리프 수 `n^(log_b a)`가 전체를 지배한다 |
| 2 | `f(n) = Θ(n^(log_b a))` | `Θ(n^(log_b a) · log n)` | 모든 레벨의 비용이 같고, 레벨이 `log n`개이다 |
| 3 | `f(n)`이 다항식만큼 크고 `a·f(n/b) ≤ c·f(n)` (c < 1) | `Θ(f(n))` | 위쪽(루트)으로 갈수록 비용이 커져 루트의 비용 `f(n)`이 지배한다 |

- `T(n−1)` 꼴(빼기 형태)은 마스터 정리 대상이 아니므로 반복 대입으로 푼다.
- `f(n)`과 `n^(log_b a)`의 차이가 다항식이 아니면(예: `n log n` vs `n`) 기본형으로 풀 수 없다.

### 1.4 분할상환 분석

#### 정의

연산을 여러 번 수행할 때, 전체 비용을 연산 횟수로 나눈 1회당 비용으로 분석하는 방법이다.

#### 등장 배경

동적 배열의 append는 대부분 `O(1)`이지만 가끔 배열을 늘리며 `O(n)`이 걸린다. 최악만 보면 `O(n)`이지만, 비싼 연산은 드물게 일어나므로 n번 전체를 보면 1회당 `O(1)`이다. 이런 연산의 실제 비용을 정확히 나타내기 위해 쓴다.

#### 분석 방법

| 방법 | 내용 |
| --- | --- |
| 집계 방법 (aggregate) | 연산 n번의 전체 비용 T(n)을 구해 n으로 나눈다 |
| 회계 방법 (accounting) | 싼 연산에 실제보다 높은 비용을 매겨 적립하고, 비싼 연산이 적립금을 쓴다 |
| 포텐셜 방법 (potential) | 자료구조의 상태에 포텐셜 함수 Φ를 정의한다. 분할상환 비용 = 실제 비용 + Φ의 변화량 |

#### 성질

| 성질 | 설명 |
| --- | --- |
| 평균 복잡도와 다르다 | 평균은 입력의 확률 분포를 가정하지만, 분할상환은 최악의 연산 순서에서도 성립하는 보장이다 |
| 동적 배열 append는 분할상환 `O(1)`이다 | 2배씩 늘리면 n번 동안 복사 총량이 `1 + 2 + 4 + … < 2n`이다 |

### 1.5 P와 NP

#### 정의

| 분류 | 정의 | 예 |
| --- | --- | --- |
| P | 다항 시간에 풀 수 있는 결정 문제 | 정렬, 최단 경로, MST |
| NP | 답(증거)이 주어지면 다항 시간에 맞는지 검증할 수 있는 결정 문제 | P의 모든 문제, SAT, 해밀턴 회로 |
| NP-완전 | NP에 속하면서, 모든 NP 문제를 다항 시간에 이 문제로 바꿀(환원할) 수 있는 문제 | SAT, 해밀턴 회로, 0/1 냅색 결정판, 외판원 결정판, 그래프 색칠 |
| NP-하드 | 모든 NP 문제가 다항 시간에 환원되는 문제. NP에 속하지 않아도 된다 | 외판원 최적화판, 정지 문제 |

#### 구조

```
┌──────────────── NP-하드 ────────────────┐
│                                          │
│   ┌──────────── NP ────────────┐         │
│   │  ┌──────┐     ┌─────────┐  │         │
│   │  │  P   │     │ NP-완전 │◄─┼── NP ∩ NP-하드
│   │  └──────┘     └─────────┘  │         │
│   └────────────────────────────┘         │
└──────────────────────────────────────────┘
(P ≠ NP라고 가정했을 때의 그림)
```

#### 성질

| 성질 | 설명 |
| --- | --- |
| `P ⊆ NP`이다 | 다항 시간에 풀 수 있으면, 직접 풀어서 검증도 다항 시간에 할 수 있다 |
| NP-완전 문제 하나를 다항 시간에 풀면 `P = NP`이다 | 모든 NP 문제가 그 문제로 다항 시간에 환원된다 |
| `P = NP`인지는 아직 증명되지 않았다 | 대부분 `P ≠ NP`라고 추측한다 |

### 용어 정리

- **입력 크기**: 알고리즘에 주어지는 데이터의 양 (원소 수, 비트 수 등)
- **기본 연산**: 수행 시간을 대표하는 연산 (정렬에서는 비교)
- **결정 문제**: 답이 예/아니요인 문제
- **환원 (reduction)**: 한 문제를 다른 문제의 풀이를 이용해 푸는 것
- **의사 다항 시간**: 입력의 값에는 다항이지만 입력의 비트 수에는 지수인 시간 (0/1 냅색의 `O(nW)`)

## 2. 연산별 시간복잡도

| 코드 패턴 | 복잡도 |
| --- | --- |
| 단순 반복 `for i in range(n)` | `O(n)` |
| 이중 반복 | `O(n²)` |
| `for i in range(n): for j in range(i, n)` | `O(n²)` (`n(n+1)/2`) |
| `i *= 2` 또는 `i //= 2` 반복 | `O(log n)` |
| `for i in range(n): j=1; while j<n: j*=2` | `O(n log n)` |
| `for i in range(1, n+1): for j in range(i, n+1, i)` | `O(n log n)` (조화수 `n·H(n)`) |
| `i*i <= n` 까지 반복 | `O(√n)` |
| 부분집합 전부 | `O(2ⁿ)` |
| 순열 전부 | `O(n!)` |

## 3. 동작 과정

### 마스터 정리

`T(n) = a·T(n/b) + f(n)` (a ≥ 1, b > 1). `n^(log_b a)`와 `f(n)` 비교.

| 경우 | 조건 | 결과 |
| --- | --- | --- |
| 1 | `f(n) = O(n^(log_b a − ε))` (f가 다항적으로 작음) | `Θ(n^(log_b a))` |
| 2 | `f(n) = Θ(n^(log_b a))` | `Θ(n^(log_b a) · log n)` |
| 3 | `f(n) = Ω(n^(log_b a + ε))` 이고 `a·f(n/b) ≤ c·f(n)` (c < 1) | `Θ(f(n))` |

예시

| 점화식 | `n^(log_b a)` | 경우 | 결과 | 대표 |
| --- | --- | --- | --- | --- |
| `T(n) = T(n/2) + 1` | `1` | 2 | `Θ(log n)` | 이분 탐색 |
| `T(n) = 2T(n/2) + 1` | `n` | 1 | `Θ(n)` | 트리 순회 |
| `T(n) = 2T(n/2) + n` | `n` | 2 | `Θ(n log n)` | 병합 정렬 |
| `T(n) = 2T(n/2) + n²` | `n` | 3 | `Θ(n²)` | |
| `T(n) = 8T(n/2) + n²` | `n³` | 1 | `Θ(n³)` | 단순 분할 행렬 곱 |
| `T(n) = 7T(n/2) + n²` | `n^2.81` | 1 | `Θ(n^2.81)` | 스트라센 |
| `T(n) = 3T(n/2) + n` | `n^1.585` | 1 | `Θ(n^1.585)` | 카라츠바 |

- 적용 안 되는 경우: `f(n)`과 `n^(log_b a)` 차이가 다항이 아닐 때 (예: `2T(n/2) + n log n` → 확장판으로 `Θ(n log² n)`)
- 빼기 형태 `T(n−1)`은 마스터 정리 대상이 아님 → 반복 대입

### 반복 대입

- `T(n) = T(n−1) + n` → `n + (n−1) + … + 1` = `Θ(n²)` (퀵 정렬 최악, 선택 정렬)
- `T(n) = T(n−1) + 1` → `Θ(n)`
- `T(n) = 2T(n−1) + 1` → `2ⁿ − 1` = `Θ(2ⁿ)` (하노이 탑)
- `T(n) = T(n/2) + n` → `n + n/2 + n/4 + … ≤ 2n` = `Θ(n)` (퀵 셀렉트 평균)

### 재귀 트리

`T(n) = T(n/3) + T(2n/3) + n`
- 각 레벨 비용 합 ≤ n
- 가장 긴 경로 깊이 `log_{3/2} n`
- → `Θ(n log n)`

### 분할상환 예: 동적 배열

용량이 차면 2배로 늘리고 전부 복사.
- n번 append 할 때 복사 횟수: `1 + 2 + 4 + … + n/2 < n`
- 전체 비용 < `n (삽입) + n (복사)` = `2n` → append 1회당 분할상환 `O(1)`
- 1.5배, 2배처럼 배수로 늘려야 성립. 고정 크기(+10)씩 늘리면 `O(n)`

## 4. 비교

| 구분 | 의미 | 예 |
| --- | --- | --- |
| 최악 | 어떤 입력이든 이 이상은 안 걸림 | 퀵 정렬 `O(n²)` |
| 평균 | 입력 분포를 가정한 기댓값 | 퀵 정렬 `O(n log n)`, 해시 `O(1)` |
| 최선 | 가장 유리한 입력 | 삽입 정렬 `O(n)` |
| 분할상환 | 연산 열 전체의 최악 합 / 연산 수 | 동적 배열 append `O(1)`, 유니온 파인드 `O(α(n))` |

| 입력 크기 n | 1초 안에 가능한 복잡도 (대략 10⁸ 연산) |
| --- | --- |
| ~ 11 | `O(n!)` |
| ~ 25 | `O(2ⁿ)` |
| ~ 500 | `O(n³)` |
| ~ 5,000 | `O(n²)` |
| ~ 1,000,000 | `O(n log n)` |
| ~ 10⁸ | `O(n)` |
