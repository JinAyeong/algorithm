# 이분 탐색

> 순차 탐색 vs 이분 탐색, lower/upper bound, 매개변수 탐색

## 1. 정의 / 핵심 성질

### 1.1 순차 탐색

#### 정의

배열의 처음부터 끝까지 원소를 하나씩 차례로 비교하며 찾는 방법이다.

#### 성질

| 성질 | 설명 |
| --- | --- |
| 정렬이 필요 없다 | 모든 원소를 확인한다 |
| 성공 시 평균 비교 횟수는 `(n + 1) / 2`이다 | 찾는 원소가 i번째에 있을 확률이 모두 `1/n`이면 `(1 + 2 + … + n) / n` |
| 실패 시 비교 횟수는 n이다 | 끝까지 확인해야 없다는 것을 안다 |
| 보초(sentinel)를 쓰면 반복마다 범위 검사를 생략할 수 있다 | 배열 끝에 찾는 값을 넣어 두면 반드시 찾게 되므로 "끝에 도달했는가" 검사가 필요 없다 |
| 자주 찾는 원소를 앞으로 옮기면 평균이 줄어든다 | 찾은 원소를 맨 앞으로(move-to-front) 또는 한 칸 앞으로(transpose) 옮기는 자기 조직화 기법 |

### 1.2 이분 탐색

#### 정의

정렬된 배열에서 가운데 원소와 비교하여, 찾는 값이 있을 수 없는 절반을 버리며 범위를 좁혀 가는 탐색 방법이다.

#### 등장 배경

순차 탐색은 n개를 모두 확인해야 할 수 있다. 데이터가 정렬되어 있으면 가운데 값 하나와의 비교로 나머지 절반을 한 번에 배제할 수 있다.

#### 구조

```
찾는 값: 23
[ 2  5  8  12  16  23  38  56  72  91 ]
              ↑ 16 < 23 → 오른쪽 절반만 남김
                   [ 23  38  56  72  91 ]
                              ↑ 56 > 23 → 왼쪽 절반만 남김
                   [ 23  38 ]
                     ↑ 찾음
```

#### 성질

| 성질 | 설명 |
| --- | --- |
| 정렬된 배열에서만 쓸 수 있다 | 가운데 값과의 대소로 한쪽을 버리려면 순서가 있어야 한다 |
| 임의 접근이 `O(1)`인 자료구조여야 한다 | 가운데 원소에 바로 가야 한다. 연결 리스트에서는 가운데까지 가는 데 `O(n)`이 든다 |
| 최대 비교 횟수는 `⌊log₂ n⌋ + 1`이다 | 비교할 때마다 범위가 절반 이하로 줄어 `⌊log₂ n⌋`번 뒤 1개가 남고, 그 1개를 비교한다 |
| 비교 과정은 결정 트리(균형 BST)로 나타낼 수 있다 | 각 노드가 한 번의 비교, 깊이가 비교 횟수이다. 트리의 높이가 최대 비교 횟수이다 |
| 탐색을 여러 번 할 때 유리하다 | 정렬 `O(n log n)`을 한 번 하면 이후 탐색은 `O(log n)`이다 |

### 1.3 하한(lower bound)과 상한(upper bound)

#### 정의

- lower bound: 정렬된 배열에서 x **이상**인 값이 처음 나오는 위치이다.
- upper bound: 정렬된 배열에서 x **초과**인 값이 처음 나오는 위치이다.

#### 구조

```
x = 2
인덱스:   0   1   2   3   4   5
값:     [ 1,  2,  2,  2,  3,  5 ]
              ↑           ↑
         lower = 1    upper = 4
```

#### 성질

| 성질 | 설명 |
| --- | --- |
| x의 개수 = upper − lower이다 | 두 위치 사이가 정확히 x인 구간이다 |
| x가 없으면 lower = upper이다 | x 이상인 첫 위치와 x 초과인 첫 위치가 같다 |
| x가 없을 때 lower bound는 x를 삽입할 위치이다 | x보다 작은 값들 바로 뒤이다 |

### 1.4 매개변수 탐색 (parametric search)

#### 정의

"조건을 만족하는 최댓값(최솟값)은?"이라는 최적화 문제를 "값이 x일 때 조건을 만족하는가?"라는 판정 문제로 바꾸고, x를 이분 탐색으로 찾는 방법이다.

#### 등장 배경

최적의 답을 직접 계산하기 어려운 문제도, 답의 후보 하나가 가능한지 판정하는 것은 쉬운 경우가 많다. 판정 결과가 x에 대해 단조로우면 이분 탐색으로 경계를 찾을 수 있다.

#### 구조

```
x:      1   2   3  ...  199  200  201  202  ...
판정:    T   T   T  ...   T    T    F    F   ...
                               ↑ 조건을 만족하는 최댓값
```

#### 성질

| 성질 | 설명 |
| --- | --- |
| 판정 결과가 단조여야 한다 (`T…T F…F` 또는 `F…F T…T`) | 경계가 하나뿐이어야 절반을 버릴 수 있다 |
| 복잡도는 `O(판정 비용 × log(답의 범위))`이다 | 답의 범위를 이분 탐색하며 매번 판정한다 |

예: 랜선 자르기(길이 L로 자르면 K개 이상 나오는가?), 입국심사(시간 T 안에 M명을 모두 심사할 수 있는가?)

### 1.5 그 밖의 탐색

| 탐색 | 정의 | 성질과 설명 |
| --- | --- | --- |
| 보간 탐색 | 찾는 값의 크기로 위치를 추정한다. `pos = lo + (x − a[lo])·(hi − lo) / (a[hi] − a[lo])` | 값이 고르게 분포하면 추정이 정확해 평균 `O(log log n)`, 치우치면 최악 `O(n)`이다 |
| 피보나치 탐색 | 피보나치 수로 구간을 나눈다 | 나눗셈 없이 덧셈·뺄셈만으로 분할 위치를 구한다 |
| 지수 탐색 | 1, 2, 4, 8, …로 범위를 넓혀 x보다 큰 값을 찾은 뒤 그 구간에서 이분 탐색한다 | 크기를 모르는(무한) 배열에서도 `O(log i)`에 찾는다 (i: 찾는 위치) |

### 용어 정리

- **탐색 키**: 찾고자 하는 값
- **성공 탐색 / 실패 탐색**: 찾는 값이 있는 경우 / 없는 경우
- **보초 (sentinel)**: 반복 종료 조건을 단순화하기 위해 끝에 넣는 값
- **결정 트리**: 비교 결과에 따라 갈라지는 탐색 과정을 나타낸 트리
- **단조성**: 값이 한 방향으로만 변하는 성질

## 2. 연산별 시간복잡도

| 탐색 | 전처리 | 평균 | 최악 | 조건 |
| --- | --- | --- | --- | --- |
| 순차 탐색 | 없음 | `O(n)` | `O(n)` | 없음 |
| 이분 탐색 | 정렬 `O(n log n)` | `O(log n)` | `O(log n)` | 정렬 + 임의 접근 |
| 보간 탐색 | 정렬 | `O(log log n)` | `O(n)` | 균등 분포일 때 유리 |
| 해시 탐색 | 테이블 생성 `O(n)` | `O(1)` | `O(n)` | 정확히 일치하는 키만 |
| 균형 BST | 생성 `O(n log n)` | `O(log n)` | `O(log n)` | 삽입·삭제가 잦을 때 |

- 탐색을 한 번만 하면 정렬 비용 때문에 순차 탐색이 나음. 여러 번(약 log n번 이상) 하면 정렬 후 이분 탐색이 이득

## 3. 동작 과정

### 이분 탐색

`[2, 5, 8, 12, 16, 23, 38, 56, 72, 91]` (인덱스 0~9)

23 찾기

| lo | hi | mid | a[mid] | 비교 |
| --- | --- | --- | --- | --- |
| 0 | 9 | 4 | 16 | 16 < 23 → lo = 5 |
| 5 | 9 | 7 | 56 | 56 > 23 → hi = 6 |
| 5 | 6 | 5 | 23 | 찾음 (3번 비교) |

25 찾기 (없음)

| lo | hi | mid | a[mid] | 비교 |
| --- | --- | --- | --- | --- |
| 0 | 9 | 4 | 16 | lo = 5 |
| 5 | 9 | 7 | 56 | hi = 6 |
| 5 | 6 | 5 | 23 | lo = 6 |
| 6 | 6 | 6 | 38 | hi = 5 → lo > hi, 실패 (4번 비교) |

### 비교 횟수 계산

n = 10의 결정 트리
- 1번 비교로 찾는 원소 1개, 2번 2개, 3번 4개, 4번 3개
- 최대 비교 `⌊log₂ 10⌋ + 1 = 4`
- 성공 탐색 평균 `(1·1 + 2·2 + 3·4 + 4·3) / 10 = 29 / 10 = 2.9`

| n | 최대 비교 횟수 |
| --- | --- |
| 100 | 7 |
| 1,000 | 10 |
| 1,000,000 | 20 |

### lower / upper bound

`[1, 2, 2, 2, 3, 5]`, x = 2
- lower bound = 1 (처음으로 ≥ 2)
- upper bound = 4 (처음으로 > 2)
- 개수 = 4 − 1 = 3

x = 4: lower = upper = 5 → 개수 0, 삽입 위치 5

### 매개변수 탐색: 랜선 자르기

랜선 `[802, 743, 457, 539]`, 11개 이상 만들 수 있는 최대 길이
- 판정 `f(L) = Σ (len // L) ≥ 11` → L이 커질수록 개수 감소 (T T T … F F F)
- lo = 1, hi = 802로 이분 탐색, f(mid)가 참이면 lo = mid + 1 (답 후보 저장), 거짓이면 hi = mid − 1
- f(200) = 4 + 3 + 2 + 2 = 11 → 참, f(201) = 3 + 3 + 2 + 2 = 10 → 거짓 → 답 200

## 4. 비교

| 기준 | 순차 탐색 | 이분 탐색 |
| --- | --- | --- |
| 정렬 필요 | X | O |
| 자료구조 | 배열, 연결 리스트 | 배열 (임의 접근) |
| 시간 | `O(n)` | `O(log n)` |
| 삽입·삭제가 잦을 때 | 유리 (정렬 유지 불필요) | 불리 (정렬 유지 `O(n)`) |

| 기준 | 이분 탐색 | 보간 탐색 |
| --- | --- | --- |
| 다음 위치 | 항상 가운데 | 값으로 추정 |
| 평균 | `O(log n)` | 균등 분포 `O(log log n)` |
| 최악 | `O(log n)` | `O(n)` |

## 5. Python 구현 / 라이브러리

- `bisect.bisect_left(a, x)`: lower bound
- `bisect.bisect_right(a, x)` (= `bisect`): upper bound
- `bisect.insort(a, x)`: 정렬 유지하며 삽입 (위치 찾기 `O(log n)` + 삽입 `O(n)`)
- 3.10부터 `key=` 인자 지원

```python
from bisect import bisect_left, bisect_right

a = [1, 2, 2, 2, 3, 5]
bisect_left(a, 2)                       # 1
bisect_right(a, 2)                      # 4
bisect_right(a, 2) - bisect_left(a, 2)  # 3
```

```python
def binary_search(a, x):
    lo, hi = 0, len(a) - 1
    while lo <= hi:
        mid = (lo + hi) // 2
        if a[mid] == x:
            return mid
        if a[mid] < x:
            lo = mid + 1
        else:
            hi = mid - 1
    return -1
```

```python
# 매개변수 탐색: 조건을 만족하는 최댓값
def parametric(lo, hi, ok):
    ans = lo
    while lo <= hi:
        mid = (lo + hi) // 2
        if ok(mid):
            ans = mid
            lo = mid + 1
        else:
            hi = mid - 1
    return ans

# 랜선 자르기
cables, k = [802, 743, 457, 539], 11
parametric(1, max(cables), lambda L: sum(c // L for c in cables) >= k)  # 200
```
