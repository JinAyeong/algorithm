# 백트래킹 · 완전 탐색

> 완전 탐색, 순열/조합, 가지치기

## 1. 정의 / 핵심 성질

### 1.1 완전 탐색

#### 정의

가능한 모든 경우를 빠짐없이 확인하여 답을 찾는 방법이다. 브루트 포스(brute force)라고도 한다.

#### 성질

| 성질 | 설명 |
| --- | --- |
| 항상 정답을 찾는다 | 모든 경우를 확인한다 |
| 경우의 수가 시간 제한 안에 들어오는지 먼저 계산해야 한다 | 경우의 수가 지수·팩토리얼로 늘어나 n이 조금만 커져도 불가능해진다 |
| 반복문, 재귀, 순열·조합 생성, 비트마스크, BFS/DFS로 구현한다 | 경우를 나열하는 방식만 다르다 |

### 1.2 경우의 수

| 종류 | 정의 | 식 | 설명 | 예 (n=5, r=3) |
| --- | --- | --- | --- | --- |
| 순열 `nPr` | 서로 다른 n개에서 r개를 골라 순서 있게 나열 | `n! / (n−r)!` | 첫 자리 n가지, 둘째 `n−1`가지, …, r번째 `n−r+1`가지 | 60 |
| 조합 `nCr` | 서로 다른 n개에서 순서 없이 r개를 고름 | `n! / (r!(n−r)!)` | 순열에서 같은 r개의 나열 순서 `r!`가지를 하나로 본다 | 10 |
| 중복 순열 `nΠr` | 중복을 허락하여 r개를 순서 있게 나열 | `n^r` | 자리마다 n가지 | 125 |
| 중복 조합 `nHr` | 중복을 허락하여 순서 없이 r개를 고름 | `(n+r−1)Cr` | r개의 공과 `n−1`개의 칸막이를 배열하는 방법의 수와 같다 | 35 |
| 부분집합 | n개 원소의 모든 부분집합 | `2^n` | 원소마다 포함/제외 2가지 | 32 |

- `nCr = (n−1)C(r−1) + (n−1)Cr`: 특정 원소 하나를 포함하는 경우와 포함하지 않는 경우로 나눈 것이다(파스칼의 삼각형).

### 1.3 백트래킹

#### 정의

해를 단계적으로 만들어 가는 과정을 상태 공간 트리로 보고 깊이 우선으로 탐색하되, 현재 상태에서 해에 도달할 수 없다고 판단되면(유망하지 않으면) 그 아래를 탐색하지 않고 되돌아가는 방법이다.

#### 등장 배경

완전 탐색은 명백히 답이 될 수 없는 경우까지 끝까지 만들어 본다. 중간 단계에서 조건 위반을 확인하고 일찍 포기하면 탐색할 경우의 수를 크게 줄일 수 있다.

#### 구조

```
4-Queen의 상태 공간 트리 (각 레벨 = 행, 가지 = 퀸을 놓을 열)

                    ( )
          ┌──────┬───┴───┬──────┐
         1열    2열     3열    4열         ← 1행
          │      │
     ┌──┬─┘      └─┐
    3열 4열        4열                       ← 2행 (1열·2열은 충돌 → 가지치기)
     X   │          │
         2열        1열                      ← 3행
          X         │
                    3열 → 해 [2, 4, 1, 3]    ← 4행
```

#### 성질

| 성질 | 설명 |
| --- | --- |
| 유망성 판단 함수(promising)의 품질이 성능을 결정한다 | 일찍, 많이 걸러낼수록 탐색하는 노드가 줄어든다 |
| 최악 복잡도는 완전 탐색과 같다 | 가지치기가 전혀 일어나지 않는 입력이 있을 수 있다 |
| 실제 탐색 노드 수는 크게 줄어든다 | 유망하지 않은 노드 아래의 서브트리 전체를 건너뛴다 |
| DFS로 탐색한다 | 현재 경로 하나만 기억하면 되어 메모리가 적다 |

### 1.4 분기 한정 (branch and bound)

#### 정의

최적화 문제에서 각 노드마다 그 아래에서 얻을 수 있는 해의 한계값(bound)을 계산하고, 한계값이 지금까지 찾은 최선해보다 나쁘면 가지치기하는 방법이다.

#### 성질

| 성질 | 설명 |
| --- | --- |
| 최적화 문제에 쓴다 | "더 좋은 해가 나올 가능성"을 수치(bound)로 비교한다 |
| BFS 또는 최선 우선 탐색(best-first)을 쓴다 | bound가 좋은 노드부터 탐색하면 좋은 해를 빨리 찾아 가지치기가 많아진다. 우선순위 큐로 구현한다 |
| 0/1 냅색, 외판원 문제에 쓴다 | 남은 물건을 쪼개 넣는다고 가정한 값(분할 가능 배낭)처럼 계산하기 쉬운 bound가 있다 |

### 1.5 대표 문제

| 문제 | 상태 | 가지치기 조건 | 설명 |
| --- | --- | --- | --- |
| N-Queen | 행마다 퀸을 놓을 열 | 같은 열, 같은 대각선 | 같은 대각선 위의 칸은 `행 − 열` 또는 `행 + 열`이 같다 |
| 부분집합의 합 | 원소마다 포함/제외 | `현재 합 + 다음 원소 > 목표` 또는 `현재 합 + 남은 합 < 목표` | 정렬된 상태에서 더 넣으면 넘치거나, 다 넣어도 모자란다 |
| 그래프 색칠 (m-coloring) | 정점마다 색 | 인접 정점과 같은 색 | 인접한 두 정점은 색이 달라야 한다 |
| 해밀턴 회로 | 다음에 방문할 정점 | 이미 방문했거나 간선이 없음 | 모든 정점을 한 번씩만 지나야 한다 |
| 스도쿠 | 빈칸마다 숫자 | 행·열·3×3 박스에 같은 숫자 | 스도쿠 규칙 |

### 용어 정리

- **상태 공간 트리**: 문제의 모든 가능한 상태(부분 해)를 노드로 나타낸 트리
- **유망하다 (promising)**: 그 노드 아래에서 해를 찾을 가능성이 있다
- **가지치기 (pruning)**: 유망하지 않은 노드의 서브트리를 탐색하지 않는 것
- **한계값 (bound)**: 노드 아래에서 얻을 수 있는 해의 최대(또는 최소) 추정치

## 2. 연산별 시간복잡도

| 탐색 대상 | 경우의 수 | 가능한 n (1초 기준) |
| --- | --- | --- |
| 부분집합 | `O(2ⁿ)` | ~ 25 |
| 순열 | `O(n!)` | ~ 10 |
| 조합 `nCr` | `O(nCr)` | r에 따라 다름 |
| 중복 순열 | `O(nʳ)` | |
| N-Queen | 최악 `O(n!)` (행마다 열 하나) | ~ 15 |
| 그래프 m-색칠 | `O(mⁿ)` | |

- 각 경우를 만드는 데 드는 비용(복사, 검사)도 곱해야 함. 예: 순열마다 길이 n 검사면 `O(n · n!)`

## 3. 동작 과정

### 4-Queen

`(행, 열)`, 행마다 1열부터 시도.

| 단계 | 시도 | 결과 |
| --- | --- | --- |
| 1 | 1행 1열 | 놓음 |
| 2 | 2행: 1열(같은 열), 2열(대각선) X, 3열 | 놓음 |
| 3 | 3행: 1열(같은 열), 2열(2행 3열과 대각), 3열(같은 열), 4열(2행 3열과 대각) | 전부 X → 되돌아감 |
| 4 | 2행 4열 | 놓음 |
| 5 | 3행 2열 | 놓음 |
| 6 | 4행: 1열(같은 열), 2열(같은 열), 3열(3행 2열과 대각), 4열(같은 열) | 전부 X → 되돌아감 |
| 7 | 3행 3열(2행 4열과 대각), 4열(같은 열) | X → 2행도 끝 → 1행으로 |
| 8 | 1행 2열 → 2행 4열 → 3행 1열 → 4행 3열 | **해 발견 `[2, 4, 1, 3]`** |

```
. Q . .
. . . Q
Q . . .
. . Q .
```
- 4-Queen 해는 `[2, 4, 1, 3]`, `[3, 1, 4, 2]` 두 개, 8-Queen 해는 92개

### 부분집합의 합

`{3, 5, 6, 7}`, 목표 15 (정렬된 상태)

```
                  (합 0, 남은 21)
            +3 /              \ −3
        (3, 18)              (0, 18)
      +5 /    \ −5             ...
   (8, 13)   (3, 13)
  +6 /  \ −6
(14, 7)  (8, 7)
 +7 X     +7 → 15 ✓ {3, 5, 7}
```
- `(14, 7)`에서 +7 → 21 > 15 → 가지치기, −7 → 14 < 15이고 남은 원소 없음 → 실패
- `(8, 7)`에서 +7 → 15 → 해
- 가지치기 조건: `현재 합 + 다음 원소 > 목표` 또는 `현재 합 + 남은 합 < 목표`

### 순열 생성 트리 (1, 2, 3)

           ( )

```python
# N-Queen
def n_queen(n):
    col, diag1, diag2 = [False] * n, [False] * (2 * n), [False] * (2 * n)
    count = 0

    def go(r):
        nonlocal count
        if r == n:
            count += 1
            return
        for c in range(n):
            if col[c] or diag1[r + c] or diag2[r - c + n]:
                continue
            col[c] = diag1[r + c] = diag2[r - c + n] = True
            go(r + 1)
            col[c] = diag1[r + c] = diag2[r - c + n] = False

    go(0)
    return count
```

```python
# 순열 직접 생성
def permute(arr, r):
    used, path, res = [False] * len(arr), [], []

    def go():
        if len(path) == r:
            res.append(path[:])
            return
        for i, x in enumerate(arr):
            if not used[i]:
                used[i] = True
                path.append(x)
                go()
                path.pop()
                used[i] = False

    go()
    return res
```
