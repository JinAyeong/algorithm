# 그리디

> 탐욕 선택 속성, 활동 선택, 그리디가 최적이 아닌 경우

## 1. 정의 / 핵심 성질

### 1.1 그리디 알고리즘

#### 정의

문제를 푸는 각 단계에서 그 순간 가장 좋아 보이는 선택을 하고, 한 번 한 선택은 되돌리지 않는 방법이다. 탐욕 알고리즘이라고도 한다.

#### 등장 배경

모든 경우를 비교하는 완전 탐색이나 동적 계획법은 시간과 메모리가 많이 든다. 어떤 문제는 매 순간의 최선 선택을 이어 붙이기만 해도 전체 최적해가 되므로, 훨씬 빠르고 단순하게 풀 수 있다.

#### 성질

그리디가 최적해를 보장하려면 다음 두 조건이 필요하다.

| 조건 | 정의 | 설명 |
| --- | --- | --- |
| 탐욕 선택 속성 | 지금의 최선 선택을 포함하는 최적해가 존재한다 | 그래야 지금 선택해도 최적해를 놓치지 않는다 |
| 최적 부분 구조 | 선택 후 남은 부분 문제의 최적해와 지금 선택을 합치면 전체 최적해가 된다 | 그래야 같은 방식을 남은 문제에 반복할 수 있다 |

| 성질 | 설명 |
| --- | --- |
| 조건을 만족하지 않으면 최적해를 보장하지 않는다 | 지금 좋은 선택이 나중에 더 좋은 선택을 막을 수 있다 |
| 보통 정렬이나 우선순위 큐와 함께 쓴다 | "가장 좋은 것"을 빠르게 고르기 위해서이다 |
| 최적이 아니어도 빠른 근사해로 쓰기도 한다 | 외판원 문제의 최근접 이웃 방법 등 |

### 1.2 그리디의 정당성 증명: 교환 논증

#### 정의

최적해가 그리디의 선택과 다르다고 가정하고, 그 부분을 그리디의 선택으로 바꿔도 해가 나빠지지 않음을 보여 그리디 선택이 최적해에 포함될 수 있음을 증명하는 방법이다.

#### 예: 활동 선택

- 그리디: 끝나는 시간이 가장 빠른 활동 g를 먼저 선택한다.
- 최적해 O의 첫 활동이 a ≠ g라고 하자. g는 a보다 일찍(또는 같이) 끝난다.
- O에서 a를 g로 바꿔도 g 이후의 활동들과 겹치지 않는다 → 개수가 같은 최적해이다.
- 따라서 g를 포함하는 최적해가 존재한다.

### 1.3 대표 문제

| 문제 | 그리디 기준 | 최적 여부 | 설명 |
| --- | --- | --- | --- |
| 활동 선택 (회의실 배정) | 끝나는 시간이 빠른 것부터 | 최적 | 일찍 끝날수록 남은 시간이 많다 (교환 논증) |
| 분할 가능 배낭 | 무게당 가치가 높은 것부터, 마지막은 쪼개서 | 최적 | 쪼갤 수 있으므로 단위 무게당 가치가 높은 것으로 채우는 것이 항상 이득이다 |
| 0/1 배낭 | 무게당 가치 순 | **최적 아님** → DP | 쪼갤 수 없어 빈 공간이 남을 수 있다 |
| 거스름돈 (단위가 서로 배수) | 큰 단위부터 | 최적 | 큰 단위 하나를 작은 단위 여러 개로 바꾸면 개수만 늘어난다 |
| 거스름돈 (일반 단위) | 큰 단위부터 | **최적 아님** → DP | 단위 {1, 4, 6}, 금액 8: 그리디 6+1+1(3개), 최적 4+4(2개) |
| 허프만 코딩 | 빈도가 가장 낮은 두 개를 합침 | 최적 | 빈도가 낮은 문자를 가장 깊은 곳에 두는 것이 평균 길이를 줄인다 |
| 최소 신장 트리 | 크루스칼, 프림, 솔린 | 최적 | 컷 성질 |
| 최단 경로 (양수 가중치) | 다익스트라 | 최적 | 가장 가까운 미확정 정점은 더 가까워질 수 없다 |
| 마감 기한 작업 스케줄링 | 이익이 큰 작업부터, 마감 직전의 빈 시간에 배치 | 최적 | 이익이 큰 작업을 최대한 늦게 배치해 앞자리를 남긴다 |
| 대기 시간 합 최소화 | 처리 시간이 짧은 작업부터 (SPT) | 최적 | 앞 작업의 처리 시간이 뒤 작업 모두의 대기 시간에 더해진다 |
| 외판원 문제 | 가장 가까운 도시부터 | **최적 아님** | 마지막에 먼 도시가 남을 수 있다 |

### 1.4 허프만 코딩

#### 정의

문자의 등장 빈도를 이용해, 자주 나오는 문자에는 짧은 코드를, 드물게 나오는 문자에는 긴 코드를 주는 가변 길이 부호화 방법이다.

#### 등장 배경

모든 문자에 같은 길이(예: 3비트)의 코드를 주면, 자주 나오는 문자도 같은 길이를 차지해 낭비가 생긴다. 빈도에 따라 길이를 다르게 하면 전체 비트 수를 줄일 수 있다.

#### 구조

빈도 a:5, b:9, c:12, d:13, e:16, f:45

```
            100
          0/   \1
        f:45    55
              0/   \1
             25     30
           0/ \1  0/  \1
         c:12 d:13 14  e:16
                 0/ \1
                a:5  b:9

코드: f=0, c=100, d=101, a=1100, b=1101, e=111
```

#### 성질

| 성질 | 설명 |
| --- | --- |
| 접두사 코드이다 (어떤 코드도 다른 코드의 앞부분이 아니다) | 모든 문자가 리프에 있으므로 한 문자의 경로가 다른 문자의 경로에 포함되지 않는다. 구분자 없이 해독할 수 있다 |
| 빈도가 가장 낮은 두 노드를 합치는 과정을 `n − 1`번 반복한다 | 합칠 때마다 노드 수가 1 줄어든다 |
| 최소 힙으로 `O(n log n)`이다 | 최솟값 두 개를 꺼내고 합친 노드를 넣는 연산이 `O(log n)`이다 |
| 접두사 코드 중 평균 코드 길이가 최소이다 | 빈도가 가장 낮은 두 문자를 형제로 가장 깊은 곳에 두는 최적해가 항상 존재한다 (교환 논증) |
| 빈도가 같을 때의 선택에 따라 코드는 달라질 수 있다 | 다만 전체 비트 수는 같다 |

### 용어 정리

- **탐욕 선택 속성**: 지역적으로 최선인 선택이 전체 최적해로 이어지는 성질
- **최적 부분 구조**: 최적해가 부분 문제의 최적해를 포함하는 성질
- **교환 논증**: 최적해의 일부를 그리디 선택으로 바꿔도 손해가 없음을 보이는 증명 방법
- **접두사 코드**: 어떤 코드도 다른 코드의 접두사가 아닌 코드 체계
- **근사 알고리즘**: 최적해를 보장하지 않지만 빠르게 좋은 해를 구하는 알고리즘

## 2. 연산별 시간복잡도

| 문제 | 복잡도 |
| --- | --- |
| 활동 선택 | `O(n log n)` (정렬) |
| 분할 가능 배낭 | `O(n log n)` |
| 거스름돈 | `O(단위 수)` |
| 허프만 코딩 | `O(n log n)` (힙) |
| 크루스칼 / 프림 | `O(E log V)` |
| 다익스트라 | `O(E log V)` |

## 3. 동작 과정

### 활동 선택

`(시작, 끝)`: (1,4), (3,5), (0,6), (5,7), (3,9), (5,9), (6,10), (8,11), (8,12), (2,14), (12,16) — 끝 시간 순 정렬 상태

| 선택 | 이유 | 마지막 끝 시간 |
| --- | --- | --- |
| (1, 4) | 첫 번째 | 4 |
| (5, 7) | 시작 5 ≥ 4 인 것 중 끝이 가장 빠름 | 7 |
| (8, 11) | 시작 8 ≥ 7 | 11 |
| (12, 16) | 시작 12 ≥ 11 | 16 |

최대 4개. 시작 시간 순이나 길이 짧은 순은 반례가 있음.

### 분할 가능 배낭 vs 0/1 배낭

용량 50, 물건 `(무게, 가치)`: (10, 60), (20, 100), (30, 120) → 비율 6, 5, 4
- 분할 가능: 10 + 20 전부 + 30의 2/3 → `60 + 100 + 80 = 240` (최적)
- 0/1에 비율 그리디: 10 + 20 → 160, 30은 안 들어감 → 160
- 0/1 최적: 20 + 30 → **220** → 그리디 실패

### 거스름돈 반례

단위 {1, 4, 6}, 금액 8
- 그리디: 6 + 1 + 1 → 3개
- 최적: 4 + 4 → **2개**
- 한국 화폐(10, 50, 100, 500)는 큰 단위가 작은 단위의 배수라 그리디가 최적

### 허프만 코딩

빈도 a:5, b:9, c:12, d:13, e:16, f:45

| 단계 | 합치는 두 개 | 힙 |
| --- | --- | --- |
| 1 | a(5) + b(9) = 14 | c12, d13, 14, e16, f45 |
| 2 | c(12) + d(13) = 25 | 14, e16, 25, f45 |
| 3 | 14 + e(16) = 30 | 25, 30, f45 |
| 4 | 25 + 30 = 55 | f45, 55 |
| 5 | f(45) + 55 = 100 | 100 |

```
            100
          0/   \1
         f45    55
              0/   \1
             25     30
           0/ \1  0/  \1
          c12 d13 14   e16
                0/ \1
               a5   b9
```

| 문자 | 빈도 | 코드 | 비트 |
| --- | --- | --- | --- |
| f | 45 | 0 | 45 |
| c | 12 | 100 | 36 |
| d | 13 | 101 | 39 |
| a | 5 | 1100 | 20 |
| b | 9 | 1101 | 36 |
| e | 16 | 111 | 48 |

- 총 224비트 (빈도 단위). 고정 길이 3비트면 300비트
- 평균 코드 길이 `224 / 100 = 2.24`비트

### 마감 기한 스케줄링

작업 `(이익, 마감)`: A(100, 2), B(19, 1), C(27, 2), D(25, 1), E(15, 3)
- 이익 순: A, C, D, B, E
- A → 시간 2 / C → 시간 1 / D: 마감 1 자리 없음 → 버림 / B: 버림 / E → 시간 3
- 결과 C, A, E → 이익 142

## 4. 비교

| 기준 | 그리디 | DP |
| --- | --- | --- |
| 선택 | 현재 최선 하나만 | 모든 선택지의 결과를 비교 |
| 되돌림 | 없음 | 저장된 결과로 비교 |
| 속도 | 빠름 | 상대적으로 느림, 메모리 사용 |
| 최적 보장 | 탐욕 선택 속성이 있을 때만 | 최적 부분 구조 + 중복 부분 문제면 보장 |
| 예 | 분할 가능 배낭, 활동 선택 | 0/1 배낭, 일반 거스름돈 |

## 5. Python 구현 / 라이브러리

```python
def activity_selection(acts):         # acts: [(start, end), ...]
    acts.sort(key=lambda x: (x[1], x[0]))
    count, last_end = 0, -1
    for s, e in acts:
        if s >= last_end:
            count += 1
            last_end = e
    return count
```

```python
import heapq

def huffman_bits(freqs):              # 총 비트 수
    h = list(freqs)
    heapq.heapify(h)
    total = 0
    while len(h) > 1:
        a = heapq.heappop(h)
        b = heapq.heappop(h)
        total += a + b                # 합칠 때마다 아래 리프들의 깊이가 1씩 증가
        heapq.heappush(h, a + b)
    return total

huffman_bits([5, 9, 12, 13, 16, 45])  # 224
```

```python
def fractional_knapsack(W, items):    # items: [(w, v), ...]
    items.sort(key=lambda x: x[1] / x[0], reverse=True)
    total = 0
    for w, v in items:
        if W >= w:
            W -= w
            total += v
        else:
            total += v * W / w
            break
    return total
```
